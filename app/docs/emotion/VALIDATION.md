# 개발 검증과 청취 검증 계획

이 기능은 **소프트웨어가 의도대로 작동하는지**와 **실제 소리 샘플에 감정 태그가 어울리는지**를 따로 확인합니다. 컴파일·자동 검사를 통과해도 감정 태그의 청취 타당성이 입증되는 것은 아닙니다.

## 1. 현재 상태

문서 기준일: 2026-11-23.

| 항목 | 상태 | 기록 원칙 |
|---|---|---|
| 선행연구 및 초기 후보 관계 | 7편과 직접 후보 9개를 문서화 | [선정 기준](CRITERIA.md)·[출처](SOURCES.md) 확인 |
| 카탈로그 자동 검사 | **통과** | JDK 21 빌드, 신규 `EmotionCatalogTest` 206개 assertion |

| 편집기 삽입·실행 취소 자동 검사 | **통과** | Linux·JDK 21·Xvfb의 Swing 검사 20개 assertion 통과 |

| 실제 앱 샘플의 청취 조사 | **미실시** | 응답 수·점수·효과크기를 추정해서 채우지 않음 |

기존 [앱 검증 기록](../VERIFICATION.md)의 통과 수는 이 새 기능의 검증 완료 수로 재사용하지 않습니다. 위 기존 검사 101개는 이번 빌드에서도 다시 통과한 결과이며, 신규 카탈로그 206개와 분리해 기록했습니다. 신규 Swing 검사 20개를 더해 이번 변경에서 총 327개 assertion을 통과했습니다. 배포 JAR의 독립 화면 실행도 확인했습니다.

## 3. 청취 조사의 목적

첫 조사의 질문은 **“음음음의 실제 재생음에서, 후보 태그가 사용자에게 탐색 기준으로 이해되고 어울리는가?”**입니다. 인간의 감정에 관한 보편 법칙을 증명하거나 음악 치료 효과를 검증하려는 조사가 아닙니다.

먼저 다음 두 과제를 나눕니다.

- **A. 소리와 태그의 적합성:** 화음 이름과 추천 태그를 숨기고 실제 샘플의 인상을 평가합니다.
- **B. 화면 사용성:** 감정 필터로 후보를 찾고 근거를 읽고 편집기에 넣는 과정을 수행합니다.

두 결과를 분리하면 태그가 맞지 않는 문제와 화면이 어려운 문제를 구분하기 쉽습니다.

## 4. 탐색용 조사 규모와 모집

첫 회는 **샘플 8–12개, 참가자 15–25명** 정도로 진행하는 안을 제안합니다. 이는 수업 프로젝트에서 부담을 조절하기 위한 **탐색용 운영 제안**이며, 통계적 검정력을 계산한 숫자나 최소 유효 표본 수가 아닙니다. 검정력에 근거한 연구를 하려면 목표 효과·분산·설계·분석 방법을 정한 뒤 별도 계산해야 합니다.

음음음의 목표 사용자에 해당하는 음악 비전공자를 포함하고, 음악 경험이 있는 사람도 구분해 기록합니다. 실제 모집 인원과 완료 인원, 제외한 응답 수 및 사유는 조사 후 사실대로 적습니다. 참여자를 아직 모집하지 않은 상태에서 인구통계나 평균을 가정하지 않습니다.

필요한 배경 항목은 연령대, 음악 학습 경험, 평소 듣는 음악, 사용한 청취 장치 정도로 한정할 수 있습니다. 이름 대신 참가자 코드를 사용하고, 이 조사와 관계없는 건강·현재 기분을 추측하거나 수집할 필요는 없습니다.

## 5. 샘플 준비

### 기본 세트

현재 7개 후보를 모두 포함합니다. 남은 항목에는 일부 동일 샘플의 반복을 넣어 개인 안에서 평가가 얼마나 흔들리는지 보거나, 비교 목적을 미리 정한 소수의 조건 변형을 넣을 수 있습니다.

예를 들어 7개 기본 샘플과 2개 반복 샘플로 9개를 구성할 수 있습니다. 이 숫자와 구성 역시 조사 설계 제안입니다. 반복 여부는 참가자에게 샘플 이름으로 드러내지 않고 바로 연달아 제시하지 않습니다.

### 재생 환경

가능하면 같은 기기·신시사이저·사운드뱅크·헤드폰·음량으로 듣게 합니다. MIDI 입력 velocity가 같더라도 앱의 전체 음량 설정과 기기의 합성 방식에 따라 실제 출력이 달라집니다. 후보들은 같은 명목 조건을 사용하지만 물리적 음압·지각된 크기가 정규화된 것은 아닙니다. 원격으로 진행하면 운영체제, 전체 음량 설정, 재생 방식, 헤드폰/스피커 사용 여부 등 환경을 기록합니다. 환경을 섞었다면 그 차이를 결과의 제한으로 적습니다.

각 샘플에 다음 메타데이터를 남깁니다.

| 기록할 것 | 목적 |
|---|---|
| 샘플 ID·카탈로그 버전 | 나중에 어떤 소리를 평가했는지 재현 |
| MIDI 구성음·전위·음역 | 코드 기호만으로 구분되지 않는 음배치 기록 |
| 악기·신시사이저·사운드뱅크·운영체제 | 실제 음색 차이 추적 |
| BPM·tick 길이·입력 velocity·전체 음량 설정 | 재생 조건 확인 |
| 반복/변형 여부 | 분석에서 원본·반복·변형 구분 |

현재 기본 미리 듣기 조건은 **GM 0, 60 BPM, 1920 tick, 입력 velocity 72**입니다. 전체 음량 설정도 고정하고 기록합니다. 청취 조사를 위해 오디오를 별도로 렌더링한다면 그 파일과 생성 조건을 새 조사 자료로 기록합니다. 논문 공개 자극 자료를 사용한 것처럼 적지 않습니다.

## 6. 블라인드 청취 절차

1. **설명과 연습:** 음악 전문지식을 시험하는 것이 아니라 소리의 인상을 묻는다는 점을 안내합니다. 본 조사에 없는 연습 샘플 하나로 조작을 익힙니다.
2. **음량 확인:** 본인이 편하게 들을 수 있는 수준을 맞춥니다. 조사 도중 크게 바꾸었다면 기록합니다.
3. **순서 무작위화:** 참가자마다 샘플 순서를 바꿉니다. 원래 TSV 순서나 감정별 묶음 순서를 그대로 들려주지 않습니다.
4. **선입견 줄이기:** 듣기 화면에는 코드 이름, 기쁨/슬픔 추천 표시, 감정색, 논문 평균을 보여주지 않습니다. 중립적인 샘플 번호를 사용합니다.
5. **반복 청취:** 다시 듣기를 허용하되 그 정책을 모든 참가자에게 같게 적용합니다.
6. **독립 평가:** 각 항목의 인상을 답하게 하고 정답 피드백을 주지 않습니다. 판단하기 어려운 항목에는 별도의 선택지를 제공합니다.
7. **휴식:** 피로해지면 잠시 쉬도록 합니다. 완료하지 못한 응답과 완료 응답을 구분합니다.

## 7. 질문 문항

첫 안내문은 다음과 같이 제안합니다.

> 지금 자신의 기분이 아니라, 방금 들은 소리가 어떤 분위기로 들리는지 평가해 주세요. 여러 표현이 동시에 어울릴 수 있고, 어울리는 표현이 없을 수도 있습니다.

다섯 태그를 각각 평가합니다.

| 문항 | 응답 |
|---|---|
| ‘기쁨’이라는 표현이 이 소리에 얼마나 어울리나요? | 1 전혀 어울리지 않음 – 5 매우 어울림 |
| ‘슬픔’이라는 표현이 이 소리에 얼마나 어울리나요? | 같은 척도 |
| ‘그리움’이라는 표현이 이 소리에 얼마나 어울리나요? | 같은 척도 |
| ‘긴장감’이라는 표현이 이 소리에 얼마나 어울리나요? | 같은 척도 |
| ‘긍정적인’이라는 표현이 이 소리에 얼마나 어울리나요? | 같은 척도 |
| 더 잘 맞는 표현이 있다면 적어 주세요. | 선택적 자유응답 |

`판단하기 어려움`은 중간점 3으로 자동 변환하지 않고 별도 응답으로 기록합니다. 특정 태그만 항상 먼저 나오지 않도록 문항 순서를 균형 있게 바꿀 수 있습니다.

위 문항은 **한국어 제품 태그의 적합성을 확인하기 위해 제안한 새 평가 문항**입니다. 2016년 논문의 원문 척도와 같은 검사지라고 주장하지 않으며, 특히 `긍정적인`의 적합성 평정을 원문의 양극형 정서가 척도와 직접 합치지 않습니다.

## 8. 실제 화면의 사용성 확인

블라인드 평가 이후 별도로 다음 과제를 제시할 수 있습니다.

1. 표현하고 싶은 분위기 하나를 정합니다.
2. ‘감정으로 화음 찾기’에서 후보를 두 개 이상 들어봅니다.
3. 한 후보의 연구 근거를 열고 그 숫자가 무엇을 뜻하는지 자기 말로 설명합니다.
4. 정한 시작 박·길이로 화음을 넣고 전체 한 마디를 들어봅니다.
5. 한 번 실행 취소하고 다시 실행합니다.

관찰할 것은 필터·듣기·근거·삽입을 스스로 찾는지, 연구 평균을 정답 확률로 오해하는지, 미리 듣기와 삽입 뒤의 악기·속도 차이를 이해하는지입니다. 성공 여부와 어려움을 기록하고, 수행 시간 등을 측정한다면 시작·종료 기준을 먼저 정합니다.

## 9. 결과 정리와 채택 판단

샘플과 태그별로 **유효 응답 수, 평균, 중앙값, SD 또는 사분위 범위, 판단하기 어려움 비율**을 기록합니다. 반복 샘플은 반복 응답이라는 사실을 반영해 다루고, 같은 사람의 여러 응답을 독립적인 참가자 수로 세지 않습니다.

문헌 평균과 새 조사값은 표를 분리합니다. 한국어 문항·재생 조건·표본이 다르면 단순히 평균이 높고 낮다는 사실만으로 재현 성공·실패를 선언하지 않습니다. 소규모 조사에서 얻은 작은 평균 차이로 추천 순위를 과도하게 정밀하게 만들지 않습니다.

| 관찰 | 다음 조치의 예 |
|---|---|
| 같은 태그가 대체로 이해되지만 샘플별 반응이 다름 | 샘플 조건과 태그 연결을 분리해 조정 |
| 특정 한국어 표현의 해석이 크게 갈림 | 용어 설명·대체 번역을 검토하고 다시 평가 |
| 논문 태그와 앱 샘플의 인상이 반복적으로 어긋남 | 연결을 보류하고 음배치·음색·조건 차이를 확인 |
| 블라인드 적합성은 괜찮지만 후보를 찾기 어려움 | 화면 흐름·명칭·재생 피드백을 수정 |
| 평균을 확률로 오해함 | 근거 화면의 숫자 설명과 표기를 수정 |

이 표는 판단 절차의 예이며 완료된 조사 결과가 아닙니다. 채택에 수치 기준을 쓰기로 한다면 결과를 본 뒤 유리하게 바꾸지 않도록 조사 전에 정의하고, 제품 운영 기준인지 통계적 근거인지 명시합니다.

## 10. 조사 후 남길 보고서

조사를 실시하면 다음을 기록합니다.

- 모집 기간·대상·참여/완료/제외 인원과 제외 사유.
- 카탈로그 버전·정확한 샘플·재생 환경·질문 문항·제시 순서 정책.
- 샘플별 응답 분포와 자유응답의 요약. 개인을 식별할 수 있는 응답은 공개 자료에서 제거.
- 유지·보류·수정한 연결과 그 이유.
- 태그 적합성과 사용성 결과의 차이, 남은 제한.
- 화면·자료를 바꾼 경우 무엇을 다시 확인했는지.

현재 이 조사에 대한 참가자 응답이나 통계 결과는 없습니다. 실제 검증을 마친 뒤에도 문헌 출처·제품 샘플·자체 평가 자료의 구분을 유지합니다.
